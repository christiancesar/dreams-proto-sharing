# dreams-proto-sharing

Package with the gRPC contracts (`.proto` files) and the code generated from them, used by the Dreams microservices. It is published to npm as `dreams-proto-sharing` and keeps client and server on the same types and methods.

Part of my Bachelor's thesis [Microservices Architecture: Projects, Patterns and Principles](https://github.com/christiancesar/dreams-origins/blob/main/docs/TCC-Christian-Cesar-2022-Arquitetura-de-Microsservicos.pdf) (UFR, 2022, in Portuguese). The microservices that consume this package are in [dreams-project-microservices](https://github.com/christiancesar/dreams-project-microservices).

Portuguese version: [README.md](README.md)

## Contracts

```
src/contracts/
├── flight/   flight.proto, flight_pb.js/.d.ts, flight_grpc_pb.js/.d.ts
├── hotel/    hotel.proto, hotel_pb.js/.d.ts, hotel_grpc_pb.js/.d.ts
├── package/  package.proto, package_pb.js/.d.ts, package_grpc_pb.js/.d.ts
└── user/     user.proto, user_pb.js/.d.ts, user_grpc_pb.js/.d.ts
```

- `*_pb`: messages (classes with getters and setters, `toObject`, serialization).
- `*_grpc_pb`: client stubs (`UsersClient`, `FlightsClient`...) and service definitions (`UsersService`...), with interfaces such as `IUsersServer`.

## Installation

```bash
npm install dreams-proto-sharing
```

The generated code needs two packages in the consuming project. The package declares them as dependencies, so npm installs them, but the project must use the same runtime version:

- `google-protobuf` 4.x (runtime of the generated code)
- `@grpc/grpc-js` 1.x (gRPC client and server)

Always import by file path. The `main` field in `package.json` points to an `index.js` that does not exist in the package:

```ts
import { UsersClient } from 'dreams-proto-sharing/src/contracts/user/user_grpc_pb';
import { UserRequest, User } from 'dreams-proto-sharing/src/contracts/user/user_pb';
```

## Versions

The package follows semver:

- **Major** (`2.0.0`): a change that breaks consumers. Version 2 requires `google-protobuf` 4.x. Code generated by version 1 still runs on `google-protobuf` 4, but code generated by version 2 does not run on 3.x.
- **Minor**: a new field or method, compatible with existing consumers.
- **Patch**: a fix with no API change.

Projects using `^1.x` stay on the 1.x line until they migrate explicitly.

## Development

Prerequisites: Node.js LTS and npm.

```bash
npm install
npm run compile   # generates the files in src/contracts from the .proto files
npm run lint      # buf lint, with the exceptions documented in buf.yaml
npm run breaking  # compares the contracts with the main branch and fails on breaking changes
```

The files are generated by `buf generate`, configured in `buf.gen.yaml`:

- Message JavaScript: official `protocolbuffers/js` plugin (remote).
- gRPC stubs: official `grpc/node` plugin with `grpc_js` (remote).
- `.d.ts` typings: `protoc-gen-ts` from `grpc_tools_node_protoc_ts`. This is the only component with no maintained replacement, and the project still uses it because consumers depend on the class-based format it produces.

Remote plugins need internet access.

## Publishing

1. Change the `.proto` and run `npm run compile`, `npm run lint` and `npm run breaking`.
2. Choose the version by the semver rules above and update `package.json` (`npm version <version> --no-git-tag-version`).
3. Check the contents with `npm pack --dry-run`. Only `src/contracts` and the READMEs go into the package.
4. Confirm the login with `npm whoami` and publish with `npm publish`.
5. Create the git tag (`git tag v<version>`) and record the change in this README.

npm does not allow overwriting a published version. If something is wrong, publish a new version.
